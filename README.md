## Project Overview

Rachel is a lightweight autonomous AI agent that combines technical pattern recognition and real-time news sentiment analysis to support futures trading decisions. It runs entirely on a local machine (optimized for Apple Silicon MPS) and exposes a React web interface for interaction.

The agent is powered by Claude (via the zeroclaw runtime) and uses two specialized tools:
- **Trading Signal Tool** — detects chart patterns (head-and-shoulders, double top/bottom, wedge, channel, triangle) using OHLCV data from yfinance
- **News Pipeline Tool** — fetches live news from Finnhub and classifies sentiment using a fine-tuned Qwen2.5-7B LoRA model

## System Architecture

```
React UI (localhost:3001)
         |
         | HTTP
         v
FastAPI Backend (api.py, localhost:8000)
         |
         | subprocess
         v
zeroclaw Agent + Claude API
         |
         |-- trading_signal.py --> TradingPatternScanner (yfinance OHLCV)
         |
         └-- news_pipeline.py  --> Finnhub API
                                       |
                                       └--> Qwen2.5-7B + LoRA (MPS sentiment)
```

**API endpoints:**
- `POST /api/chat` — sends a message to the zeroclaw agent, returns response
- `GET /api/kline?symbol=GC=F` — returns 15-minute OHLCV candles (yfinance)
- `GET /api/news?symbol=Gold&limit=5` — returns Finnhub news with sentiment scores
- `POST /api/chat/mcp` — alternative chat endpoint using Claude API directly with MCP tool servers

## MCP Architecture (Additional Path)

### What is MCP?

Model Context Protocol (MCP) is an open standard protocol developed by Anthropic that defines how AI models invoke external tools. Unlike proprietary plugin systems, any MCP-compatible AI client can connect to an MCP server and use its tools without additional integration work.

### zeroclaw Skills vs. MCP

| | zeroclaw Skills | MCP |
|---|---|---|
| Protocol | Proprietary zeroclaw Skill format | Open standard (Anthropic MCP) |
| Compatibility | zeroclaw agent only | Any MCP-compatible AI client |
| Tool definition | `SKILL.md` files | Python MCP server exposing named tools |
| Usage in Rachel | Default path | Additional standardized path |

### MCP Servers in This Project

**`trading_signal_server.py`** — exposes `get_trading_signals` tool
- Wraps `trading_signal.py` (TradingPatternScanner)
- Input: symbol, interval, period
- Output: detected chart patterns as structured text

**`news_pipeline_server.py`** — exposes `get_news_sentiment` tool
- Wraps `news_pipeline.py` (Finnhub + Qwen2.5-7B)
- Input: symbol, limit
- Output: news articles with sentiment scores and overall verdict

### Dual-Path Architecture

```
Path 1 — Default (zeroclaw):
User → FastAPI (/api/chat)
         └→ zeroclaw Agent (Claude backbone)
               └→ Skills
                     ├→ trading_signal.py  (TradingPatternScanner)
                     └→ news_pipeline.py   (Finnhub + Qwen2.5-7B)

Path 2 — MCP:
User → FastAPI (/api/chat/mcp)
         └→ Claude API (direct)
               └→ MCP Protocol
                     ├→ trading_signal_server.py → trading_signal.py
                     └→ news_pipeline_server.py  → news_pipeline.py
```

### Switching Between Modes

In the **AI tab** of the React UI, an **Engine toggle** allows switching between the two paths:

- **⚡ zeroclaw** (default) — routes to `/api/chat`, uses the zeroclaw agent with Skills
- **🔌 MCP** — routes to `/api/chat/mcp`, uses Claude API directly with MCP tool servers

zeroclaw remains the primary path. MCP is provided as an additional standardized path that demonstrates open-standard tool invocation.

## Step-by-Step Setup

### 1. Clone the repository

```bash
git clone <repo-url>
cd Lightweight-Multi-Tool-Agent-Rachel-for-Futures-Signal-Detection-and-News-Aware-Decision-Support
```

### 2. Clone TradingPatternScanner (local dependency)

```bash
git clone https://github.com/white07S/TradingPatternScanner ~/TradingPatternScanner
```

### 3. Install Rust

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source $HOME/.cargo/env
```

### 4. Build zeroclaw

```bash
cd zeroclaw
cargo build --release
```

This takes 5–10 minutes. The binary will be at `zeroclaw/target/release/zeroclaw`.

### 5. Set up your .env file

```bash
cp .env.example zeroclaw/.env
# Open zeroclaw/.env and fill in your actual API keys
```

### 6. Initialize the zeroclaw agent

```bash
cd zeroclaw
./target/release/zeroclaw onboard --provider anthropic
```

Follow the interactive prompts to configure the agent.

### 7. Set the default model in config

After onboarding, open `~/.zeroclaw/config.toml` and make sure `default_model` is set to a valid model:

```toml
default_model = "claude-haiku-4-5-20251001"
```

### 8. Install Python dependencies

```bash
pip install fastapi uvicorn yfinance finnhub-python transformers peft torch accelerate python-dotenv
```

### 9. Install zeroclaw skills

```bash
cd zeroclaw
./target/release/zeroclaw skills install skills/news_pipeline/
./target/release/zeroclaw skills install skills/news_analyzer/
./target/release/zeroclaw skills install skills/news_search/
./target/release/zeroclaw skills install skills/trading_signal/
```

### 10. Sync scripts to workspace

```bash
cd zeroclaw
bash sync.sh
```

### 11. Install frontend dependencies

```bash
cd trading-ui
npm install
```

## Running the Project

Open two terminal windows:

**Terminal 1 — Backend:**
```bash
cd zeroclaw
FINNHUB_API_KEY=$(grep FINNHUB_API_KEY .env | cut -d= -f2) uvicorn api:app --host 0.0.0.0 --port 8000
```

**Terminal 2 — Frontend:**
```bash
cd trading-ui
npm start
```

Open your browser at **http://localhost:3000** or **http://localhost:3001**.

## Fine-Tuning

Rachel uses two fine-tuned models:

**Fine-tune 1 — News Summarization and Sentiment Analysis (Jess Liang)**
- Base: Qwen/Qwen2.5-7B-Instruct
- Adapter: [Jessliang/rachel-finetuned](https://huggingface.co/Jessliang/rachel-finetuned)
- Task: Summarize financial news articles in 1–2 sentences and classify sentiment (Positive / Neutral / Negative)
- Training data: Financial news corpus prepared by Nicole

**Fine-tune 2 — Agent LLM replacement (planned)**
- Approach: Knowledge distillation from Claude (Anthropic) to a smaller open-source model
- Goal: Replace the Claude API backbone with a locally-hosted model for cost reduction
